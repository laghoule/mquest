## Core System Issues (High Priority)

- **Animation & Positioning**: The movement system relies heavily on `pending_tick` for position adjustments (`action.asm`:52, `input.asm`:67). This creates instability and potential timing issues. Needs a more robust tick-based animation system with proper interpolation or delta-time calculations.
- **Collision Detection Gaps**:
  - Character-to-character collision exists in `collis.asm` but is inconsistently applied (see below)
  - Scene transitions (`transit.asm`) only check object collisions, missing character interaction checks during boundary crossings
- Use JA/JB (not-signed) instead of JG/JL (signed).
- Ensure memory aligment for 8086 (16 bit)
- Use TEST only for bit masking testing (use CMP instead)
- **Right-edge character wrap (`x = LIMIT_EAST = 305`)**: at the east edge, the 16-pixel character blit in `DRAW_CHARACTER_VGA` (`src/gfx/char/render.asm`) writes one byte past the 320-pixel scanline: VGA offset `+320` wraps to `x = 0` on the next line. At the same position, `CROP_METATILE_RAM` / `RESOLVE_MAP_TILES` (`src/gfx/tile.asm`) selects the tile at `x + 15 = 320`, which is outside the 20-tile-wide scene and resolves to the first tile of the next tile row. This can produce a one-pixel column artifact at the right edge. Review `LIMIT_EAST` / the transition threshold and/or clip the blit to `SCREEN_WIDTH - CHAR_WIDTH = 304`.
